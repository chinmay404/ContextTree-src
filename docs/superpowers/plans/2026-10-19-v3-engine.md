# Context Tree V3 Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the FastAPI engine the only writer of V3 board data. It gets the board API, computes each chat's read set, feeds that set into the prompt, adds answer strings and carry modes, and ingests notes, files, web pages and YouTube cards. The V2 frontend keeps working on the same database throughout.

**Architecture:** Migration 009 adds columns only. New routers (`board`, `cards`, `edges`, `reads`, `sources`) use small store modules that build on `PostgresConversationStore`'s pool, and they share one error envelope (`ApiError`). The read set comes from a pure function, `compute_reads(BoardGraph, chat_id)`, which runs over one board snapshot loaded in a few queries. The context builder (`app/agent/board_context.py`) uses that read set instead of `contextNodeIds` whenever the chat is a V3 card. The V2 paths (`get_related_file_context`, `contextNodeIds`, `/files/ingest` for V2 nodes) stay the same in behaviour.

**Tech Stack:** Python 3.13 (`.venv`), FastAPI 0.139, Pydantic v2, raw psycopg2 + pgvector (768-dim), LangGraph, slowapi, pytest 9 against a local Docker `pgvector/pgvector:pg16`.

**Spec:** `ContextTree-src/docs/superpowers/specs/2026-10-19-v3-board-design.md`. This plan covers §5 in full, the engine side of §6, the engine half of §8 and the engine tests in §9. The binding contract is `ContextTree-src/docs/superpowers/plans/2026-10-19-v3-api-contract.md`.

## Contract changes requested

Before execution, apply these to `2026-10-19-v3-api-contract.md` in a commit of their own and tell the frontend and integration executors. This plan already assumes them.

1. **Chat body gets an optional `boardId`.** V3 clients send it (`ChatRequest` already has `boardId`, so `HttpEngineApi` only has to forward it). When `boardId` is present, or the node row has `kind` set, the engine treats the turn as V3:
   - the card must be a live chat on that board, owned by the caller. If it is missing, deleted, on another board or someone else's, the engine returns 404 `not_found`. If the card is a source, it returns 400 `invalid`.
   - the engine never creates a node for a V3 turn.
   - Without `boardId`, the engine cannot tell a missing V3 card from a V2 node that has not been saved yet. That is why the spec's "requires the card to exist" needs this field.
2. **`SourceData.off?: boolean`.** It marks a pile member as switched off on the pile card (spec §4: "Pile reads as the union of its members that are not switched off"; prototype `m.off`). The read set leaves out members with `off: true` entirely.
3. **Clarifications (no shape change).** Each line is the behaviour the engine implements:
   - **Id owned by another user.** `POST` with an id that already belongs to another user → 409 `duplicate`.
   - **Messages of a source.** `GET …/cards/{id}/messages` for a source → 400 `invalid`, the same as `…/reads`.
   - **Edge endpoint missing.** `POST /edges` whose `from` or `to` card is missing or on another board → 404.
   - **Orphan restore.** `POST …/restore` on a card whose parent chat is still deleted → 409 `not_allowed`.
   - **Restore over the cap.** `POST …/restore` that would push the board past 50 live cards → 409 `card_limit`.
   - **Uploads count.** `POST …/sources/file|link` count toward the 50-card cap → 409 `card_limit`.
   - **Repeated source id.** Re-posting an existing source id returns 200 with the existing card and does not ingest again.
   - **Lineage edges in GET board.** `GET /boards/{b}` returns lineage edges only when both end cards are live. A deleted branch therefore draws no tube, and restore brings the tube back.
   - **Every HTTP error uses the envelope.** 401 and 429 included: `{"error","detail"}`. The existing `detail` key stays, so V2 callers keep working.

## Spec notes (choices made inside the spec's latitude)

- **Token budget key.** The spec's `advanced.budget` is the contract's `advanced.contextBudgetTokens`. The engine reads it from the card's `data`, not from the chat body.
- **V3 file retrieval has its own query.** It lives in `app/agent/board_context.py` and returns `node_id`, `score` and `metadata.loc`. `get_related_file_context`, which V2 still calls, stays byte-identical, so V2 cannot regress.
- **No backfill swap (decided 2026-10-19, supersedes spec §8 wording).** V2 `'Context'` edges get `kind='wire'` but keep their V2 direction (chat→file). V3 never reads V2 canvases, and swapping would make V2 draw reversed arrows and race V2's whole-canvas save. Only V3 creates source→chat wires.
- **V2 keeps writing `kind IS NULL` edges after 009.** The lineage fallback (Task 7) therefore treats `kind IS NULL AND condition='Fork'` as lineage too.

## Global Constraints

- **No destructive schema change.** Schema changes are additive only: no rename, drop, retype or NOT NULL on existing columns. Migration 009 must be idempotent and forward-only (spec §3, §5.6).
- **Production database.** Production uses the same database. No agent connects to it.
  - `scripts/migrate.py` loads `.env` (prod), so always run it with `DATABASE_URL=postgresql://postgres:ctxdev@localhost:55432/v3test` inline.
  - Never print or copy values from `.env*`, `DB.txt`, `*.pem` or `V2/08-CHECKPOINT.md`.
- **Tenancy.** The tenancy key is `user_email`; the JWT `sub` is the email (resolve with `store.resolve_user_email(user_id)`). Every query is scoped by `user_email`. A missing, deleted or foreign board, card or edge → 404, never 403.
- **Error body.** `{"error": "<code>", "detail": "<optional>"}`. Codes:
  - 400 `invalid`
  - 409 `card_limit` | `duplicate` | `not_allowed`
  - 413 `too_large` · 415 `unsupported_type`
  - 404 `not_found` · 401 `unauthorized`
- **JSON shape.** JSON is camelCase on the wire (contract §Types).
- **Ids.** Ids come from the client and match `^[A-Za-z0-9_-]{1,100}$`. Every create is `ON CONFLICT (id) DO NOTHING`. Re-posting your own id → 200 with the existing object.
- **Write scope.** Each write touches one entity. No endpoint infers a delete from absence. Deletes are soft (`deleted_at`). Every read filters `deleted_at IS NULL`.
- **Prod-shaped inserts.** Prod tables come from the V2 frontend init (`lib/mongodb.ts:68-139`):
  - `nodes.data`, `canvases.data`, `edges.canvas_id` and `edges.user_email` are NOT NULL.
  - `user_email` references `users(email)`.
  - Every engine INSERT therefore sets `data` (at least `'{}'`), `canvas_id` and `user_email`.
- **Card cap.** 50 live cards per board (`kind IS NOT NULL AND deleted_at IS NULL`), checked under `pg_advisory_xact_lock(hashtext('board:' || board_id))`.
- **Limits and clip lengths.**
  - Upload cap: 4 MB (`4 * 1024 * 1024` bytes), over → 413.
  - Note text: 4 000 chars.
  - Linked answer: 3 000 chars. Linked summary: 1 200 chars.
  - Overview: one call to `settings.SUMMARY_MODEL_NAME`. Key passages: up to five.
  - CSV: one chunk per 40 rows, `loc = 'rows a–b'` (en dash); 200 rows kept for the table view.
- **Token estimate.** `ceil(chars / 4)`.
- **Carry `whole`.** At most the last 40 messages and at most 12 000 tokens (48 000 chars). Anything older goes into the summary.
- **Rate limit.** Every new route takes `request: Request` and is decorated with `@limiter.limit(BOARD_RATE, key_func=user_key)`, where `BOARD_RATE = "600/minute"`. This keeps the 100/hour per-IP default from blocking proxied traffic.
- **No real LLM or embedding calls in tests.**
  - Embeddings are deterministic (`unit_emb(i)`).
  - LLMs are `FakeLLM`, monkeypatched at the module that imported `get_llm` or `get_embedding(s)`.
  - Network calls (oEmbed, page fetch) are stubbed.
- **Test commands.** `PYT` in this plan means: `cd D:/code/context_tree/ContextTree && TEST_DATABASE_URL=postgresql://postgres:ctxdev@localhost:55432/v3test .venv/Scripts/python.exe -m pytest`

## Review Focus

1. **Default IP rate limit.** `limiter` has `default_limits=["100/hour"]` per IP, and all V3 traffic comes from a few Vercel proxy IPs. The board polls every 2 s while a card is processing, so it would get 429s within a minute.
   - Expected: board routes are limited per user, not per IP.
   - Test: `test_board_routes_not_capped_by_default_ip_limit` (Task 2).
2. **Embedding failure looks like success.** `get_embeddings` swallows provider errors and returns zero vectors. Ingest would then mark a source `ready` with chunks that retrieve nothing.
   - Expected: the card goes to `failed` with an error.
   - Test: `test_ingest_zero_embeddings_marks_failed` (Task 12).
3. **Prod tables are V2-frontend-shaped, not `001`-shaped.** `edges` may have no `meta` column, which would make the backfill fail mid-deploy and abort the migration.
   - Expected: 009 applies cleanly to frontend-shaped tables.
   - Test: `test_009_applies_on_v2_frontend_shaped_tables` (Task 1).
4. **Restoring a branch whose parent is still deleted** would leave an orphan that reads wrong.
   - Expected: 409 `not_allowed`.
   - Test: `test_restore_child_under_deleted_parent_is_409` (Task 4).
5. **Bad position batches.** Positions with `NaN`, `Infinity` or `1e309`, or more than 200 entries, from a buggy spring loop.
   - Expected: 400 `invalid`, never a 500 or a stored NaN.
   - Tests: `test_positions_non_finite_is_400` and `test_positions_over_200_is_400` (Task 3).

```sql
-- 009_v3_board.sql — V3 board columns. Additive, idempotent, safe for the live V2 frontend.
-- Spec: ContextTree-src/docs/superpowers/specs/2026-10-19-v3-board-design.md §5.6, §8.
-- Nothing is renamed, dropped, retyped or made NOT NULL. Re-running is a no-op
-- (IF NOT EXISTS everywhere; the backfills only touch kind IS NULL rows).

ALTER TABLE nodes ADD COLUMN IF NOT EXISTS kind text;            -- 'chat' | 'source'
ALTER TABLE nodes ADD COLUMN IF NOT EXISTS source_type text;     -- note|pdf|doc|web|video|audio|csv|image|pile
ALTER TABLE nodes ADD COLUMN IF NOT EXISTS x double precision;
ALTER TABLE nodes ADD COLUMN IF NOT EXISTS y double precision;
ALTER TABLE nodes ADD COLUMN IF NOT EXISTS desk_id text REFERENCES nodes(id) ON DELETE SET NULL;
ALTER TABLE nodes ADD COLUMN IF NOT EXISTS pile_id text REFERENCES nodes(id) ON DELETE SET NULL;
ALTER TABLE nodes ADD COLUMN IF NOT EXISTS status text;          -- processing|ready|failed|soon (sources)
ALTER TABLE nodes ADD COLUMN IF NOT EXISTS deleted_at timestamptz;
ALTER TABLE edges ADD COLUMN IF NOT EXISTS kind text;            -- lineage|wire|answer
ALTER TABLE edges ADD COLUMN IF NOT EXISTS deleted_at timestamptz;
-- Prod's edges table was created by the V2 frontend init, which has no `meta`.
-- The backfill below reads both, so make sure both exist.
ALTER TABLE edges ADD COLUMN IF NOT EXISTS meta jsonb;
ALTER TABLE edges ADD COLUMN IF NOT EXISTS data jsonb;
ALTER TABLE canvases ADD COLUMN IF NOT EXISTS title text;
ALTER TABLE canvases ADD COLUMN IF NOT EXISTS board_version smallint;  -- 3 = V3 board; NULL = V2 canvas
ALTER TABLE canvases ADD COLUMN IF NOT EXISTS deleted_at timestamptz;

-- ADD COLUMN IF NOT EXISTS never fixes a wrong column type: abort on drift.
DO $$
DECLARE drift text;
BEGIN
  SELECT string_agg(format('%s.%s is %s, want %s', c.table_name, c.column_name, c.data_type, w.typ), '; ')
    INTO drift
  FROM (VALUES
    ('nodes','kind','text'), ('nodes','source_type','text'),
    ('nodes','x','double precision'), ('nodes','y','double precision'),
    ('nodes','desk_id','text'), ('nodes','pile_id','text'),
    ('nodes','status','text'), ('nodes','deleted_at','timestamp with time zone'),
    ('edges','kind','text'), ('edges','deleted_at','timestamp with time zone'),
    ('edges','meta','jsonb'), ('edges','data','jsonb'),
    ('canvases','title','text'), ('canvases','board_version','smallint'),
    ('canvases','deleted_at','timestamp with time zone')
  ) AS w(tbl, col, typ)
  JOIN information_schema.columns c
    ON c.table_schema = current_schema() AND c.table_name = w.tbl AND c.column_name = w.col
  WHERE c.data_type <> w.typ;
  IF drift IS NOT NULL THEN
    RAISE EXCEPTION '009_v3_board: column type drift: %', drift;
  END IF;
END $$;

CREATE INDEX IF NOT EXISTS nodes_desk_idx ON nodes(desk_id);
CREATE INDEX IF NOT EXISTS nodes_pile_idx ON nodes(pile_id);
CREATE INDEX IF NOT EXISTS edges_to_kind_idx ON edges(to_node, kind);

-- §8 backfill: edges.kind only. V2 canvases are not converted.
UPDATE edges SET kind = 'lineage'
WHERE kind IS NULL
  AND COALESCE(meta->>'condition', data->'meta'->>'condition') = 'Fork';

-- V2 stored chat→file. Direction is left as V2 wrote it: V3 never reads V2 canvases.
UPDATE edges SET kind = 'wire'
WHERE kind IS NULL
  AND COALESCE(meta->>'condition', data->'meta'->>'condition') = 'Context';
```

  - If `live_card_count + len(set) > 50` → 409 `card_limit` (under `lock_board`).

**Algorithm** (server version of the prototype `ctx()`, spec §5.2):

```python
def compute_reads(g, chat_id):
    chat = g.cards[chat_id]
    top_k = int((chat.data.get("advanced") or {}).get("externalContextTopK") or 5)

    def item(card, how, via):
        if card.kind == "chat":
            state = "ready" if card.id in g.has_answer else "waiting"
        else:
            state = card.status or "processing"
        tokens = estimate_tokens(card, g, top_k) if state == "ready" else 0
        return ReadItem(card.id, how, via, False, False, state, tokens)

    def expand(src, how, via):                       # piles read as their members not switched off
        if src.source_type == "pile":
            return [item(m, how, via) for m in g.members(src.id) if not m.data.get("off")]
        return [item(src, how, via)]

    def own(c):
        out = []
        for s in g.desk_sources(c.id):
            out += expand(s, "desk", c.id)
        for s in g.wired_sources(c.id):
            if s.desk_id != c.id:
                out += expand(s, "wire", c.id)
        out += [item(a, "answer", c.id) for a in g.answer_chats(c.id)]
        return dedupe_first(out)                     # first occurrence of a card_id wins

    def effective(c, seen, keep_hidden=False):
        items = own(c)
        parent = g.cards.get(c.parent_id or "")
        if parent and parent.kind == "chat" and c.data.get("inheritDesk", True) is not False and parent.id not in seen:
            have = {i.card_id for i in items}
            items += [replace(i, inherited=True)
                      for i in effective(parent, seen | {c.id}) if i.card_id not in have]
        hide = set(c.data.get("hide") or [])
        def is_hidden(i):                            # a hidden pile hides all its members
            return i.card_id in hide or (g.cards[i.card_id].pile_id or "") in hide
        if keep_hidden:                              # only the asking chat lists its hidden items
            return [replace(i, hidden=is_hidden(i)) for i in items]
        return [i for i in items if not is_hidden(i)]        # hidden upstream = gone for branches

    items = effective(chat, frozenset(), keep_hidden=True)
    total = sum(i.tokens for i in items if not i.hidden and i.state == "ready")
    return Reads(chat_id, items, total)
```
